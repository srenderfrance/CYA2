# Production review and consolidated backlog

Review date: **2026-11-04**. This is the authoritative current backlog; the older TODO documents retain implementation history and link here. Application code was not changed during this review.

## Import safety implementation follow-up

The original findings below are retained as review history. [Atomic staged imports](IMPORT_SAFETY.md) now replace the split backup/delete/insert flow: complete workbook validation, temporary staging outside the persistent transaction, atomic backup/replacement/contact publication, process/database write coordination, pin-aware matching snapshot retention and complete touched-donor snapshots. Migration 003 adds reliable rapid-snapshot ordering. Accounting partial-write retry/fallback is removed.

- **A01–A03:** source fixes implemented; actual MySQL failure/recovery and separate-process concurrency acceptance remain open. No SQL runtime success is claimed.
- **A04 / D02:** donation publication now emits Donations and DonorContacts invalidation, including conservative invalidation on unknown commit outcomes. Processor tests pass; warm-cache UI/rollback acceptance remains open.
- **A10:** direct and queued terminal outcomes now consider Errors and zero publication as well as FailedRows, with cancellation/unknown-outcome progress reporting. Audit remains fail-open, the queue is not durable, and post-commit reporting/cache work is not transactional.
- **Review-gap follow-up:** rollback verifies pinned markers after uncertain commit acknowledgements and preserves partial/unknown results for invalidation. Committed upload notification failures now produce warnings rather than failed-publication reports. Populated malformed rows are rejected instead of silently skipped, and frequency history matches donor identity plus fund. Focused regression tests cover these paths; actual disconnect, migration-recovery and warm-cache UI acceptance remain open. No broader donor reporting or contact DateModified completion is implied.
- **A13 / D14:** 11 synthetic workbook/coordination cases pass without Docker. The expanded 11 opt-in MySQL cases remain unexecuted locally. Real-format UI uploads, forced commit-acknowledgement loss, migration-failure recovery and production-environment acceptance remain open.

These changes do not resolve A05–A09, remaining A10 requirements, release gating or other review gates. The validation table below records the original review baseline, not the import follow-up test totals.

## Executive assessment

**Not ready for real donor/financial data yet.** The app has substantial protections and passing tests, but source inspection identifies import recovery, contact freshness, donor reporting and session/diagnostic gaps. Production-environment acceptance has not been demonstrated. A passing build is not a launch approval.

Use three stages below: **A — work possible now**, **B — deploy privately and verify before going live**, **C — ongoing improvements**. An item in A or B marked **Gate** must be resolved or have an explicit, time-limited owner-approved exception before launch; financial integrity/privacy failures should not be deferred merely because the user count is small. Other improvements can be scheduled with a named owner. The sole maintainer can approve releases: no required PRs or second-person production approval are assumed.

Evidence labels:
- **Confirmed:** directly supported by current source; not necessarily runtime-reproduced.
- **Verify:** credible concern or deployment condition requiring a targeted test.
- **Implemented:** source/test coverage exists, with environment acceptance separately tracked.
